# ADR-0004: patrol を「1リポ深掘り・自己完結の把握→疑う→探す」に再設計する

- ステータス: 採用
- 日付: 2026-07-07
- 関連: ADR-0001 を supersede する

## 文脈

ADR-0001 は spar と並ぶ第二の入口 patrol を「GitHub org を巡回し、負債レンズでランク付けして『考えた方が良いこと』を発掘し、疑うのは下流（spar / アクション）に委ねる」設計で導入した。二入口の境界軸は「悩みがあるか（spar）／ないか（patrol）」だった。

だがこの設計は自己矛盾を抱えていた。patrol は「結論を出さない・論点を置くだけ」を identity にしながら、実際は rank 付け・負債分類をし、さらに「flow 負債で打ち手が明確なものは spar を飛ばして直接アクション（close 等）」していた。close すべきという結論を、疑いを飛ばして出している。しかもその判定を read-only メタデータだけで下すが、「その放置 PR は意図的に parked か／close で文脈を失わないか」は read-only では判定できない。patrol が最も弱い場所が「疑いを飛ばす経路」になっていた。

## 決定

patrol を、**1つの repo / ディレクトリを深く読み、その場で敵対的に疑い、整理すべき話題を掘り起こす**自己完結型に再設計する。

- **内部は三段の一本道**: 把握（深く読む）→ 疑う（敵対的に叩いて綻びを surface）→ 探す（綻びを話題化）。「疑う」を下流に委ねず patrol 内で完結させる。
- **二入口の境界軸を差し替える**: 「悩みがあるか／ないか」ではなく「**話題が手にあるか（spar）／これから掘るか（patrol）**」。spar と patrol は同じ「疑う」エンジンを共有する。
- **identity を精緻化**: 「結論を出さない」を廃し「**確定・実行はしない（疑って話題を置くが、選ぶのは人間）**」に。spar を飛ばす直接アクション経路は廃止する。
- **負債レンズを再位置づけ**: 「疑う」の一レンズに降格。深く読む前提により、メタデータだけでなく実体（コード ↔ doc の矛盾・書かれざる決定）まで届く。放置（issue / PR / branch / in-flight）は flow の綻びとして拾う。
- **既定は1リポ深掘り**。複数 repo / org 横断は二次モードとし、コスト対策の二段構え（横断ランク → 上位だけ精読）はそこにのみ残す。

## 理由

自己矛盾（結論を出さないと言いつつ triage する）と read-only 判定不能を、パッチではなく設計で消す。「疑う」を patrol 内に取り込めば、疑い済みの話題として出すので「確定はしない」と矛盾なく言え、深く読むので放置の要否も断定を避けつつ話題として置ける。境界軸を「話題が手にあるか」に変えることで、spar と patrol が同じエンジンを共有する構造が素直に立つ（旧軸「悩みの有無」は表層で、深層は入力＝話題を持っているかだった）。

第二入口を残す判断（プラットフォーム化せず skill 追加で実現、放射状・疎結合）は ADR-0001 のまま引き継ぐ。変えたのは patrol の内実と境界軸であって、二入口という座組みそのものではない。

3 条件の確認: 後戻り困難（入口の設計は organize の identity に直結し、利用者が依存する skill の契約変更は難しい）／文脈なしには驚く（ADR-0001 の「patrol は結論を出さず巡回して発掘する」を読んだ者が新 patrol を見ると驚く）／実トレードオフ（自己完結の一貫性・深さ vs org 俯瞰の即時性を二次モードに降ろす損失、1リポ深掘りの視野の狭さ）。
