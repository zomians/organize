# ADR-0004: spar の doc 化を draft first（会話に出す下書きへの赤入れ）にする

- ステータス: 採用
- 日付: 2026-08-13

## 文脈

spar は §1 で一問一答・推奨案付きの質問を重ね、§2 で signal を逆引きして doc に当てる。だが **doc 本文そのものを利用者に見せる手が無く**、「合意してから書く」順序に固定されていた。

未言語化の情報は、白紙から思い出させる（recall）より、具体物への違和感として指摘させる（recognition）方が出る。§1 の鍛え方（矛盾の即指摘・曖昧語の正準化・シナリオでのストレステスト・コードとの照合）はいずれも「既に出た発言を叩く」手で、**発言が無い所を埋める手が無い**。結果、成果である md の充実度が利用者の言語化のコツに依存していた。

論点は 4 つ。(1) draft を会話に出すかファイルに書くか。(2) 既定の手にするか、詰まったときのフォールバックにするか。(3) §1（鍛え方）に置くか §2（doc 化フロー）に置くか。(4) 粒度を何で決めるか。

## 決定

§2 の doc 化フローに **draft first** を一段挟む。signal 逆引き → **doc 本文の draft を会話に提示 → 赤入れ** → 作成 / inline 更新、の順にする。

- **会話に出すだけ**（ファイルにしない）。赤入れ確定後に既存フローでファイル化する。
- **既定の手**とする。条件付き発火（詰まったとき / 材料が揃ったとき）にしない。書けない箇所は `<?>` で明示し、そこだけ問う。
- **§2 に置く**（§1 には追加しない）。**patrol には波及させない**。
- **粒度は signal が指す範囲**。doc 単位でも固定行数でもない。

## 理由

- **ファイルに書かない理由**: 合意前の本文がファイルとして在ると「決定済み」と誤読される。出口が「何も残さず終える / handoff」だったときにゴミが残り、出口の設計に後片付けの仕事が生える。既存規律「issue / PR 下書きなどの作業ファイルは作らない（本文は会話で提示し、コマンドへは stdin で渡す）」と同型に揃えれば、新しい例外を作らずに済む。lazy 作成が禁じるのは「signal が出る前に作ること」と「空の placeholder」なので、signal 後に出す draft は原則自体とは衝突しないが、ファイル化した瞬間にこの誤読と後片付けを抱え込む。
- **既定にする理由**: フォールバックにすると詰まりの検知に依存するが、最も危ないのは「スラスラ答えているが浅い」ケースで、これは検知できない。「材料が揃っているときだけ」も判定が assistant の主観でドリフトする（patrol の判定を場当たりなヒューリスティクスにせず核心から演繹させたのと同じ理由）。既定化による想像の混入は、選択肢を絞るのではなく `<?>` の明示で潰す — 何が埋まらないかが可視化される分、白紙で問うより引き出せる。spar は §1 で既に推奨案というアンカーを打つ設計なので、新しい思想を持ち込むわけではない。
- **§1 に置かない理由**: §1 に並ぶ手はすべて利用者の発言という input がある前提の「叩く」手で、draft first は input が無い所を埋める手。混ぜると「鍛え方＝叩き方」の輪郭がぼやける（ADR-0001 が「spar に分岐を増やすと spar の輪郭がぼやける」を理由に patrol を分離したのと同じ懸念）。draft を catalog の doc 本文に限定したので、居場所は catalog 側＝ §2 が素直。
- **patrol に波及させない理由**: patrol は結論を出さず、出力をファイル化せず、揮発リストを置くだけの skill。doc draft を持ち込むとこの identity とぶつかる。§2 に置けば spar 限定で自然に閉じる。
- **粒度を signal に従属させる理由**: §2 は既に「走査ではなく逆引き」＝ signal が範囲を決める設計なので、新しい判定軸が要らない。doc 丸ごとの draft は未 surface の項目まで書くことになり、`<?>` だらけの draft は赤入れ対象ではなくアンケート用紙になる。固定行数は doc 差（CONTEXT の用語 1 件と ARCHITECTURE の構造説明）を吸収できない。

3 条件の確認: 後戻り困難（全案件に配布される spar の対話契約で、doc 化の既定入口が「問う」から「見せて直させる」に変わる）／文脈なしには驚く（「lazy 作成・空の placeholder を置かない・作業ファイルを作らない」と読んだ者が、合意前に doc 本文を書く spar を見ると順序が逆に見えて驚く。会話に留めてファイルを作らないことがその驚きを解く鍵）／実トレードオフ（アンカリングによる想像の混入 vs 引き出し力、既定化のコスト vs 質問だけの軽さ、揮発の軽さ vs ファイルの見やすさ）。
