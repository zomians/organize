# implement

整理ワークフローの「実装」フェーズ。issue の次、commit の前に発火する。テストを仕様の写しとして先に書き、green を品質の担保にする。

## 前提

- **仕様の所在**: issue（FR・受け入れ基準・テスト計画）が今回の差分、リポジトリの仕様書（`API.md` / `DATA.md` 等、あれば）が恒久的な正。両方を読んでから始める
- **branch**: `feature/<#>-<summary>` 上で行う。main 上なら先に切る
- **TDD の要否は issue が決める**: テスト計画が `N/A`（理由つき）なら手順 1〜3・5 を飛ばし、手順 4 → 6 → 7 のみ行う。テスト計画が空欄・曖昧なら、着手前に issue を `gh issue edit` で直すよう提案する（実装中に要否を判断しない）

## 手順

区切り（FR 等）ごとに 1〜7 を 1 サイクルとして回す。

1. **テスト**: issue の FR・受け入れ基準・テスト計画（TC-n）から、その区切りのテストを書く。ソースはまだ書かない。仕様書と issue が食い違っていたら、書かずに止まって利用者に問う（意図した変更なら同じ branch で仕様書を更新し、そうでなければ issue を直す）
2. **red 確認**: テストを実行し、**期待どおりの理由で** fail することを確認する（構文エラー・import エラーでの fail は red と数えない）。結果（件数・TC）を控える
3. **テストレビュー**: read-only のサブエージェントにレビューさせる
   - Agent tool、`model: sonnet`、fork しない（実装の会話を渡さない）
   - 渡すのは **issue 本文・関連する仕様書・テストの diff だけ**（ソースは渡さない）
   - 観点は「テストが仕様の写しか」だけ: FR / 受け入れ基準 / TC のうちテストが無いもの、assert が期待結果とずれているもの、仕様に無いことを検証しているもの、issue と仕様書の食い違い
   - findings は本体が直し、手順2 の red を再確認する。**再レビューはしない**。直した内容を控える
   - issue と仕様書の食い違いが挙がったら、直さず止まって利用者に問う（手順1 と同じ）
4. **ソース**: テストを green にするソースを書く
   - **テスト凍結**: 手順3 を通ったテストは書き換えない。変更が必要だと判断したら、または green に届かなければ、止まって理由を添えて利用者に問う。承認されたら手順1 からやり直す
   - 凍結は `git diff` でテストファイルの変更が無いことで確かめる
5. **green 確認**: テスト全体を実行し、green を確認する。red が残る間は手順6 に進まない
6. **commit**: `commit` skill を通して 1 commit する（このサイクルのテスト＋ソース）
7. **次へ**: 区切りが残っていれば手順1 へ。すべて終わったら手順8 へ
8. **ソースレビュー**: branch 全体の diff に対して前景 `/code-review low` を走らせる
   - findings を利用者に提示する。**ソフトゲート** — 判断は人間に委ねる（直す / そのまま進む / 中断）。findings で機械的に止めない（ADR-0003）
   - **自動実行モードのとき**: read-only で走らせ（`--fix` しない）、findings を控えて止まらず次へ進む。findings は create-pr が PR と一緒に提示する
9. **create-pr へ**: 控えた red 確認結果・green 結果・テストレビューで直した内容・（自動実行時は）ソースレビューの findings を渡して `create-pr` skill へ促す

## 自動実行モード

spar の「PRまで自動実行」で yes を選んだ連鎖から起動されたときに限る（単発呼び出しは通常どおり＝fail-closed）。implement に畳む確認ゲートは無い。ただし次の場面は**自動実行でも止まって問う**（確認ではなく仕様の決定なので畳まない）:

- issue と仕様書の食い違い
- テスト凍結の破れ（テスト変更が必要）
- green に届かない

## 禁止

- 手順3 を通ったテストを、利用者の承認なく書き換えない
- red を確認せずにソースを書き始めない
- テストレビューのサブエージェントにソースや実装の会話を渡さない
